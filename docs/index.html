What QEMU models

These presets provide a generic Q35/ICH9 virtual PC. They do not emulate the 336H silicon, NPU, Intel integrated GPU, Wi-Fi 7 radio, laptop panel, or the physical machine's performance.

Pro2 and Pro2NoCap advertise 1920x1200 as a preferred VGA EDID mode. The guest graphics driver and desktop settings determine the final resolution and DPI.

Getting started

Install dependencies

sudo apt install libgtk-3-0t64 libepoxy0 \
  libpixman-1-0 libglib2.0-0t64 zlib1g

Extract a package, then run its launcher with a Debian amd64 installer ISO:

sh ./run.sh /path/to/debian-amd64.iso

After installation, run sh ./run.sh to boot from the included NVMe image.

Custom 64-vCPU / 64-GiB setup

QEMU's Q35 machine accepts 64 vCPUs. A 64 GiB guest also needs sufficient host memory; the build host used for these packages cannot allocate that much. A 2 TiB qcow2 image is supported and is sparse until data is written. 

qemu-img create -f qcow2 supercomputer.qcow2 2T
qemu-system-x86_64 -machine pro2nocap \
  -smp 64 -m 64G -accel kvm -cpu host \
  -drive file=supercomputer.qcow2,if=none,id=ssd,format=qcow2 \
  -device nvme,drive=ssd,serial=supercomputer

KVM and -cpu host require a compatible Linux host. Host CPU, RAM, and storage remain the limiting factors.

About the 8.20 GHz request

QEMU cannot force a VM to execute at 8.20 GHz. Guest throughput depends on the host CPU and accelerator; QEMU has no execution-frequency cap to remove.

A guest TSC frequency setting can report a chosen timer rate, but it does not make instructions execute faster and may affect guest timekeeping. KVM can approach host performance when available, not exceed the host processor's capabilities.
